# 인별납부내역자동화 (TaxCheck)

졸업생 기금 납부 내역 분석 및 오류 자동 검출 도구

## 개요

NiceGUI 기반 웹 애플리케이션으로, 졸업생의 기금 납부 내역을 분석하여 다음 오류를 자동으로 검출합니다:

- **미납**: 해당 월에 납부 기록이 없는 경우
- **부족**: 기준금액보다 적게 납부한 경우
- **초과**: 기준금액보다 많이 납부한 경우

## 기술 스택

- Python 3.12
- NiceGUI 2.0+
- Pandas 2.0+
- openpyxl 3.1+
- NumPy 1.26+

## 시작하기

### 사전 요구사항

- Python 3.12+
- pip

### 설치 방법

```bash
# 저장소 클론
cd 인별납부내역자동화

# 가상환경 생성 및 활성화
python -m venv TaxCheck/venv
source TaxCheck/venv/bin/activate  # Linux/Mac
# TaxCheck\venv\Scripts\activate   # Windows

# 의존성 설치
pip install -r TaxCheck/requirements.txt
```

### 실행 방법

```bash
cd TaxCheck
python app.py
```

브라우저에서 `http://localhost:10010` 접속

## 환경 변수

| 변수명 | 필수 | 설명 |
|--------|------|------|
| `GSHEET_URL` | 아니오 | Google Sheets 졸업생 명단 URL (환경변수로만 설정, 기본값 없음) |

로컬 실행 시 `.env` 파일을 프로젝트 루트에 생성:

```env
GSHEET_URL=https://docs.google.com/spreadsheets/d/...
```

> `.env` 파일은 `.gitignore`에 등록되어 있어 git에 커밋되지 않음.
> Render 등 클라우드 배포 시에는 플랫폼의 환경변수 설정 기능 사용.

## 사용법

1. **원본 엑셀 업로드**: 납부 내역이 포함된 엑셀 파일 (.xlsx)
2. **분석 기간 설정 (선택)**: 시작년도 ~ 종료년도
3. **졸업생 명단 확인**: `GSHEET_URL`의 명단이 자동 연결되며, 실패하면 **다시 연결** 클릭
4. **분석 실행**: 파일 업로드와 명단 연결이 완료되면 분석 실행
5. **결과 확인**: 오류 대상 건수와 대상자 수를 확인하고, 결과 파일 준비가 완료되면 다운로드

결과 화면의 오류 대상은 미납 전체와 차액의 절댓값이 1,000원 이상인 부족/초과 건입니다.
1,000원 미만의 부족/초과 내역도 결과 엑셀에는 유지됩니다.
오류검출결과 시트는 처음 열 때 `오류 대상 = O` 필터가 적용되어 있습니다.
엑셀에서 해당 컬럼의 필터를 해제하면 전체 내역을 다시 볼 수 있습니다.
`오류 대상`은 맨 오른쪽 컬럼이며, 헤더 메모에서 판정 기준을 확인할 수 있습니다.

`초과부족` 시트는 오류 대상인 초과·부족 내역을 이름 가나다순, 개인 내 월 최신순으로 표시합니다.
상단에 이름·년월·운영·협력·복지 헤더를 표시하고, 각 월은 납부금액·기준금액의 2행으로 구성됩니다.
이름·년월은 병합 없이 납부금액 행에만 반복 표시하며 아래쪽 정렬합니다.
납부금액은 아래쪽, 기준금액은 위쪽 정렬하고 두 행 사이의 가로선은 표시하지 않습니다.
미납과 오류 대상이 아닌 소액 차액은 제외합니다.
`미납` 시트는 `초과부족` 오른쪽에 위치하며, 이름·년월별 미납 기금명을 한 셀에 모아 표시합니다.
두 시트 모두 분석 기간 중 원본 파일명의 기준월보다 3개월 이상 이전인 내역만 표시합니다.
예를 들어 기준월이 2026-11이면 2026-08까지 포함하고 2026-09부터 제외합니다.
원본 파일명에서 기준월을 추출할 수 없으면 결과 파일 준비 단계에서 오류를 안내합니다.
다른 시트와 결과 화면 집계에는 이 추가 기간 제한을 적용하지 않습니다.
`초과부족` 시트의 크기는 Windows 화면 배율 125%, Excel 확대 100% 환경을 기준으로
A·B열 110픽셀, C~E열 120픽셀, 납부금액 행 34픽셀, 기준금액·헤더 행 36픽셀, 표 사이 빈 행 28픽셀에 맞췄습니다.
다른 배율에서는 화면 픽셀 크기가 달라질 수 있습니다.

## 분석 입력 준비와 결과 저장

첫 화면에서 졸업생 CSV의 필수 컬럼을 확인하고 데이터를 미리 준비합니다.
페이지별로 최대 5분간 재사용하며, URL 변경·유효기간 만료·재연결 시 다시 받습니다.
만료 후 조회가 실패하면 오래된 명단으로 분석하지 않고 오류를 안내합니다.
업로드 파일은 업로드 직후 백그라운드에서 읽고, 다시 업로드하면 새 파일로 교체합니다.
분석을 바로 실행해도 진행 중인 입력 준비를 기다려 같은 작업을 중복 실행하지 않습니다.

분석 직후 화면은 메모리에 있는 DataFrame을 바로 사용합니다. 서버 세션에는
결과를 JSON 문자열로 저장해 레코드별 변경 추적 비용을 줄이며, 새로고침 시에는
이 문자열 또는 이전 버전의 사전 형식 결과를 복원합니다.
오류 검출의 기금 존재 여부는 금액이 아닌 기록 수로 판단하므로 0원 납부와
납부·취소의 합계가 0원인 경우도 기존 판정을 유지합니다.

## 엑셀 생성 성능 로그

셀 서식은 통합문서 안에서 템플릿으로 재사용하며, 셀마다 복사하여 개별 수정이
다른 셀에 전파되지 않도록 합니다. 전후월 금액은 월별 합계에서 조회해 열 단위로
반영하고, 개인별·기금별 요약은 연도·상태별 그룹 집계로 계산합니다.
오류검출결과 시트는 행 단위로 직접 기록해 중간 셀 생성과 임시 서식 지정을 줄이며,
기존의 빈 값·숫자·날짜·수식 표현은 유지합니다.

Render 로그에서 `excel_stage`를 검색하면 전후월 집계, 각 시트 작성,
개인별·기금별 요약 집계와 서식, 저장·압축, 메모 위치 보정 시간을 확인할 수 있습니다.
각 단계에 `event=start`와 `event=complete`가 기록됩니다.

- `wall_s`: 실제 경과 시간(초)
- `cpu_s`: 해당 작업 스레드가 사용한 CPU 시간(초)
- `peak_rss_mb`: 프로세스 시작 이후의 최대 메모리 사용량(MiB), 미지원 환경은 `unavailable`
- `details`: 행·열 수 또는 파일 크기 등 해당 단계의 처리 규모

`stage=total`이 전체 생성 시간입니다. 요약 시트 단계에는 하위 단계가 포함되므로
모든 단계의 시간을 단순 합산하지 않습니다. 파일명·이름·납부금액은 성능 로그에 기록하지 않습니다.

## 입력 데이터 형식

### 원본 엑셀 (필수 컬럼)
- `이름`: 납부자명
- `코드1`: 기금 구분 (1=운영, 2=협력, 3=복지)
- `코드2`: 세부 코드
- `입금`: 납부 금액
- `해당년`/`해당월`: 납부 년월

### Google Sheets (졸업생 명단)
- `이름`: 졸업생명
- `구분`: "졸업생" 값이 있는 행만 필터링
